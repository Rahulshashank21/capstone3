# Feature Specification: Subscriber Self-Registration & Rule-Driven Activation (AC-01, AC-08)

**Specification ID:** SPEC-ACTIVATION-01  
**Target Criteria:** AC-01, AC-08, NFR-03, NFR-08  
**Domain Area:** Subscriber Onboarding & Activation Engine  

---

## 1. Overview
The subscriber onboarding journey comprises two distinct phases:
1. **Self-Registration (AC-01)**: The prospective customer provides their 10-digit mobile number, identity proof reference (stubbed Aadhaar/PAN/Passport ID), and preferred plan type (`PREPAID` or `POSTPAID`). The system instantiates a subscriber in the `PENDING_KYC` state. Unmasked PII is never exposed to untrusted layers or plain logs.
2. **Rule-Driven Activation (AC-08)**: To transition from `PENDING_KYC` to `ACTIVE`, the subscriber must satisfy four strict verification gates:
   - **KYC Verification**: Stub check verifying identity proof against national repository. Must evaluate to `VERIFIED`.
   - **Dealer Authorization**: The on-boarding dealer code must exist in the whitelisted master registry (`DEALER_001`, `DEALER_002`, `OFFICIAL_WEB`).
   - **MNP Validation**: For ported numbers, the Mobile Number Portability clearinghouse status must not be `REJECTED`.
   - **Duplicate Active Number Guard**: The mobile number must not already have an existing subscription in the `ACTIVE` state.

---

## 2. Acceptance Criteria

### AC-01: Self-Registration Journey
- **Given** a valid 10-digit mobile number (e.g., `9876543210`), identity proof reference `ID-REF-999`, and preferred plan type `PREPAID`,
- **When** the self-registration endpoint is invoked,
- **Then**:
  1. A subscriber record is persisted with an autogenerated ID matching `SUB-[a-f0-9]{8}`.
  2. The initial state is set to `SubscriberState.PENDING_KYC`.
  3. The response payload returns masked PII: mobile number formatted as `XXXXXX3210` and identity proof as `[REDACTED]`.

### AC-08.1: Successful Activation
- **Given** a subscriber in `PENDING_KYC` state,
- **When** activation is invoked with `kyc_status="VERIFIED"`, `dealer_code="DEALER_001"`, `mnp_status="APPROVED"`, and a valid published `initial_plan_id`,
- **Then**:
  1. Subscriber state transitions to `SubscriberState.ACTIVE`.
  2. `current_plan_id` is linked and `plan_activated_at` is set to current UTC timestamp.
  3. The mobile number is registered in active number index.

### AC-08.2: Activation Rule Violations & Specific Error Codes
- **Given** a subscriber in `PENDING_KYC` state,
- **When** activation evaluation encounters rule failures:
  - If `kyc_status != "VERIFIED"` (e.g., `REJECTED` or `PENDING`), raise `ActivationFailedException` with reason code `ERR_KYC_FAILED`.
  - If `dealer_code` is unauthorized (e.g., `INVALID_DEALER_99`), raise `ActivationFailedException` with reason code `ERR_INVALID_DEALER`.
  - If `mnp_status == "REJECTED"`, raise `ActivationFailedException` with reason code `ERR_MNP_REJECTED`.
  - If the mobile number is already `ACTIVE` in another subscription, raise `ActivationFailedException` with reason code `ERR_DUPLICATE_ACTIVE_NUMBER`.
- **Then** the subscriber remains in `PENDING_KYC` state (or moves to `TERMINATED` if permanently rejected), and no active subscription is provisioned.

---

## 3. Data Integrity & PII Rules
- Raw mobile numbers must be stored in secure fields and masked as `XXXXXX<last-4>` on all external API projections.
- Identity proof values must be hashed or replaced by `[REDACTED]` in all logger outputs.
